Attention and the transformer

What an LLM actually does, between the moment a tokeniser turns your prompt into integer IDs and the moment the model emits the next token. The conceptual foundation that every other doc in this folder implicitly assumes.

i
Reference architecture: the dense decoder-only transformer used by Qwen3-8B-NVFP4, Llama-3.1-8B, gpt-oss-20b, and almost every open-weights chat model in this project's catalog. If you already know what attention is and can sketch a transformer block on a whiteboard, skip to §6 (KV cache mechanics) — that's where this doc connects back to the bandwidth math in llm-tokens-and-speed.

1. The 30 000-foot view

A modern LLM is, mechanically, a function that takes a sequence of integer token IDs and produces a probability distribution over the next integer token ID.

Internally, the model:

  1. Looks up each token ID in an embedding table to get a vector of numbers.
  2. Runs that sequence of vectors through L identical transformer blocks (36 blocks for Qwen3-8B). Each block updates each vector in light of every other vector in the sequence.
  3. Projects the final vector for the last position through an output matrix (the "lm_head") that turns it back into a vector of 151 936 logits — one score per possible next token.
  4. Picks one token from those logits using a sampling strategy (see sampling-strategies).

Steps 2 and 3 are the entire workload. Step 1 is a memory lookup (cheap). Step 4 is arithmetic on a 151 936-element vector (also cheap). Almost every interesting thing in an LLM happens inside the 36 transformer blocks of step 2.

2. Embeddings — turning token IDs into vectors

The vocabulary has vocab_size entries (151 936 for Qwen3). The model holds an embedding matrix E of shape [vocab_size, hidden_size] — for Qwen3-8B that is [151 936, 4 096]. Each row is a learned vector for one vocabulary token.

The embedding table is also where the lm_head lives at the output end. In tied-embedding models like Qwen3, the same matrix E is used for both the input lookup and the final projection back to vocab logits.

3. The transformer block — anatomy

Every transformer block in a Qwen3-style decoder is identical in shape:

The key features:

  • Pre-norm: RMSNorm runs before attention and MLP, not after. Standard since GPT-2's "pre-norm" variant.
  • Residual stream: each sub-block adds its output back to the input.
  • Two sub-blocks per layer: attention (mixes information across positions) and MLP (transforms information within a position independently).
  • L identical layers: 36 for Qwen3-8B. Each has its own learned parameters — they are not weight-shared.

4. Attention from scratch

Self-attention is the mechanism that lets a transformer block mix information across positions — it is the only place where the representation at one token position depends on the representations at other token positions.

The mnemonic: each token broadcasts a key (a label for itself), emits a value (what it would contribute to attending tokens), and casts a query (a description of what it wants from elsewhere).

4.2 Dot-product attention

The model decides "how much should position i attend to position j?" by taking the dot product q_i · k_j:

  • Causal masking: in a decoder, position i can only attend to positions 0..i.
  • Scaled by √d_head: prevents the softmax saturating when d_head is large.
  • The output is a weighted sum of values, not keys. Q and K are the addressing scheme; V is the payload.

5. Multi-head, GQA, and why Qwen3-8B has "8 KV heads"

A single attention head has limited capacity. Real transformers use multi-head attention: split the 4096-dim vector into many smaller-dim heads, run independent attention on each, concatenate.

For Qwen3-8B (config.json excerpt):

"hidden_size": 4096,
"num_attention_heads": 32,
"num_key_value_heads": 8,
"head_dim": 128

Read the config as:

  • head_dim = 128 — each head operates on 128-dim sub-vectors.
  • num_attention_heads = 32 — 32 query heads, each with its own projection. Total Q dimensionality = 32 × 128 = 4096.
  • num_key_value_heads = 8 — only 8 independent K and V heads. The 32 Q heads are partitioned into 8 groups of 4; each group shares one (K, V) head.

That last bullet is Grouped-Query Attention (GQA) (Ainslie et al. 2023, arXiv:2305.13245). For Qwen3-8B, GQA shrinks the per-token KV from 36 × 32 × 128 × 1 B (MHA equivalent) to 36 × 8 × 128 × 1 B — exactly the 72 KB/token.

6. KV cache mechanics — and the bandwidth tie-in

This is the section that links every other doc in the project together.

6.1 What the KV cache stores

Recall from §4: attention at position i needs k_0..k_i and v_0..v_i to compute the output. Each of those K and V vectors was itself computed from x_0..x_i via the projections x · W_K and x · W_V.

Naive approach

Every time you generate a new token, recompute all K and V for the entire sequence so far. Cost is quadratic in sequence length. Untenable.

KV cache approach

After computing k_i and v_i for each new token, save them. The next token only computes its own q_{i+1}, k_{i+1}, v_{i+1} and reads the cached k_0..k_i, v_0..v_i. Per-token compute is now constant in sequence length.

The cost shifts from compute to memory: the KV cache is the data that must be read from VRAM at every decode step.

6.2 Why this lines up with the bandwidth math

For Qwen3-8B-NVFP4 at decode step N:

  • Read all model weights: ~5.1 GB (NVFP4 + BF16 embed)
  • Read entire KV cache so far: N × 72 KB bytes (FP8 KV)

At low context (N small), KV is tiny and decode is bandwidth-bound on weights. At high context, KV starts to dominate. At N = 70 000 tokens, the KV cache (~5 GB) is roughly equal to the weights — and beyond that, it dominates the per-token byte budget.

This is why bench-results's 98.3 tok/s for Qwen3-8B-NVFP4 is measured on short prompts. At 128 K context, the same model would slow to roughly 640 / (5.1 + 9.4) ≈ 44 tok/s.

6.3 Prefill vs decode in light of KV cache

Prefill

Runs the model once on all N prompt tokens in parallel. Computes k_i, v_i for every i, populates the KV cache in one pass. Compute-bound because there are N independent matrix multiplications happening on the same weights.

Decode

Runs the model once per generated token. Only computes one new (q, k, v) triple per layer per step. The big per-step cost is reading the cache and the weights, not computing matmuls. Memory-bandwidth-bound.

7. Positional encoding — RoPE, and why context extension is hard

The attention sub-block, as described in §4, treats the sequence as a set — there is nothing in q · k that knows position 5 came before position 47. The model has to be told.

The classical approach (GPT-2, BERT) was learned absolute positional embeddings. Modern models instead use Rotary Position Embeddings (RoPE) (Su et al. 2021, arXiv:2104.09864): 

for each pair of dimensions (2j, 2j+1):
    theta_j = 10000 ^ (-2j / d_head)
    rotate (q[2j], q[2j+1]) by angle (i × theta_j) at position i
    rotate (k[2j], k[2j+1]) by angle (i × theta_j) at position i

The crucial property: the dot product q_i · k_j after rotation only depends on the difference i − j, not the absolute positions.

7.1 Why this matters operationally

Qwen3-8B's config.json declares max_position_embeddings: 40960 — the natively trained context. But the project uses it at 131 072 ctx successfully. How?

RoPE scaling techniques — YaRN, Dynamic NTK, Longrope — modify the theta schedule so the rotation angles slow down at long positions. The model can then attend over longer ranges than it was trained on, with some quality degradation. vLLM and SGLang apply these via --rope-scaling flags.

The shapes for Qwen3-8B (config.json):

  • gate_proj: [hidden=4096, intermediate=12288] — expand
  • up_proj: [hidden=4096, intermediate=12288] — expand
  • down_proj: [intermediate=12288, hidden=4096] — project back

The MLP holds roughly 3× the parameters of the attention sub-block in each layer (3 × 4096 × 12288 ≈ 150 M vs attention's ~50 M). This is why "where do the parameters of an 8 B model live" answers as "two-thirds in MLPs, one-third in attention, plus embeddings".

9. RMSNorm — keeping activations stable

Modern transformers use RMSNorm (Zhang & Sennrich 2019, arXiv:1910.07467) instead of classic LayerNorm:

Compared to LayerNorm, RMSNorm:

  • Drops the mean-subtraction (assumes activations are roughly zero-centred already);
  • Drops the bias term (just a learned per-channel gain);
  • Is roughly 25 % cheaper to compute.

10. Putting one full layer together

For each layer l in 0..35, given input x of shape [N, 4096]:

# Attention sub-block
h    = rmsnorm_attn(x)                  # [N, 4096]
q, k, v = h @ W_Q, h @ W_K, h @ W_V     # split into heads, apply RoPE
# update KV cache: append k, v to layer l's cache
attn = scaled_dot_product_attention(q, K_cache, V_cache, causal=True)
x    = x + attn @ W_O                   # residual add

# MLP sub-block
h    = rmsnorm_mlp(x)
x    = x + W_down @ (silu(W_gate @ h) * (W_up @ h))   # SwiGLU + residual

Stack 36 of these layers. Then:

x_final     = rmsnorm_final(x)          # final norm
logits_last = x_final[N-1] @ E^T        # tied embedding → vocab logits
                                        # shape [vocab_size = 151 936]

Sample a token from logits_last, append it to the sequence, and run the loop again — this is decode.

W_K and W_V are 4× narrower than W_Q and W_O because of GQA. That asymmetry, multiplied across 36 layers, accounts for the ~1 GB the model "saves" by being GQA instead of MHA.

12. Why this all matters operationally

  • Every "decode is bandwidth-bound" claim flows from §6. The KV cache is the unavoidable per-token read; weights are the unavoidable per-step read. Quantisation shrinks one (NVFP4), GQA + FP8-KV shrink the other.
  • Every "context length is expensive" claim flows from §4 and §6. Attention is O(N) per generated token because of caching, but reads O(N) bytes per layer.
  • Every "different model, different parser" claim from bench-results traces back to chat templates and tool-call formats. The model's internal shape is the same; the interface differs.
  • Every "quantisation hurts X but not Y" claim is about which buckets in §11 you touch. Quantising MLPs (the bulk) saves a lot. Quantising attention W_O is risky. Quantising lm_head is forbidden by most NVFP4 checkpoints.
